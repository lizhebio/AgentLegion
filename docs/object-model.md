# AgentLegion Object Model

## 1. Resource Overview

AgentLegion uses multiple explicit resources instead of one overloaded manifest.

| Resource | Purpose |
|---|---|
| `AgentUnit` | A registered agent in the legion. |
| `CapabilityProfile` | What the agent can do and under which constraints. |
| `LegionPlan` | A composition of multiple AgentUnits and roles. |
| `MissionSpec` | A mission submitted to the legion. |
| `MissionStep` | A unit of work inside a mission. |
| `PolicySpec` | Safety, approval, and side-effect rules. |
| `RuntimePlan` | Adapter-compiled native execution plan. |
| `RuntimeHandle` | Reference to an applied runtime session/run. |
| `Artifact` | Structured output produced by agents. |
| `AgentEvent` | Normalized event envelope with raw runtime payload. |

## 2. AgentUnit

An AgentUnit describes one member of the legion.

Required fields:

- `id`
- `runtime.class`
- `runtime.adapter`
- `description`
- `capabilities`
- `interfaces`
- `safety`

An AgentUnit should not claim that the runtime is portable. It should declare what the legion can safely ask it to do.

## 3. CapabilityProfile

Capabilities describe operational ability.

Example dimensions:

- domains
- actions
- input types
- output types
- strengths
- weaknesses
- state support
- side-effect surfaces

## 4. LegionPlan

A LegionPlan groups AgentUnits into a working formation.

It defines:

- units
- roles
- routing rules
- max parallelism
- default policies
- escalation rules

## 5. MissionSpec

A MissionSpec describes what the legion should accomplish.

It contains:

- goal
- context
- constraints
- workflow
- expected outputs
- approval requirements

## 6. Artifact

Artifacts are the primary medium of collaboration.

Artifact types:

- `finding`
- `evidence_bundle`
- `plan`
- `patch`
- `review`
- `report`
- `decision`
- `run_log`

Artifacts should include:

- producer
- mission id
- content ref
- evidence
- timestamps
- status

## 7. RuntimePlan

A RuntimePlan is generated by a Runtime Adapter.

It must include:

- selected native runtime
- native config
- exposed tools
- permissions
- sandbox coverage
- expected artifacts
- approval points
- warnings
- unsupported fields

The RuntimePlan is more important than the manifest for auditability.

## 8. RuntimeHandle

A RuntimeHandle is returned after applying or invoking a RuntimePlan.

It includes:

- runtime class
- agent unit id
- mission id
- task id
- session id
- run id
- native reference
- current phase
